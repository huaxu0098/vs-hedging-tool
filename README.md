# VS × Hype 多品种动态对冲匹配器

本地中文决策工作台。用 VS 考核账户和 Hyperliquid 永续合约的独立规格、余额、已有仓位和可成交报价，计算可开上限、差额调仓、固定失败线、通过或首次出金线，以及 Hype 强平缓冲。决策工作台使用本地模拟账本。需要操作已登录的官方交易页面时，打开独立的双边开仓工具。

## 双边网页开仓

在本仓库运行 `npm run trade` 或双击「打开双边开仓.command」，即可启动服务、生成扩展并打开独立交易页。[本机双边开仓](http://127.0.0.1:4178/trade.html)

1. 初次使用时，在 Chrome 的扩展管理页打开开发者模式，选择「加载已解压的扩展程序」，选中本项目的 `build/trade-extension` 文件夹。刷新本机及两边官方页面。交易版包含当前页的只读采集功能。
2. 点「打开两个官网」，在相同 Chrome 配置中分别登录。Vest 选择具体考核或出金账户，展开当前账户概览与完整持仓。Hype 使用英文桌面版和主钱包。回到工具的「行情接入」，输入 Hype 公开钱包地址、确认映射，点击「开始自动识别」。若 Vest 只显示账户名称，在开仓页的「连接交易页与扩展」点「绑定 Vest 当前账户」，再亲自点官网当前账户名旁的复制图标，60 秒内返回开仓页。账户或徽标变化时重新核对身份。核对实际费率、杠杆、考核目标和账户失败线。
3. 页面列出本次增量买卖数量及估计名义额。切换「本次预计净盈亏」旁的情景，可查看 VS 通过、VS 失败及 Hype 强平时的条件结果。已到账现金、相对初始本金的累计盈亏及未到账分成分别列示。
4. 点击「一键双边开仓」会准备并核对两个官网市价表单，按已核实的账户和数量分别点击委托。跨平台委托可能只成交一边。钱包签名、官方确认及查看实际成交由本人完成。中断或提交后回执保留，核对两边委托与持仓后才能开始下一笔。实际成交滑点取决于当时的盘口和官网设置。
5. 「平台已发生的事件」读取当前 Vest 账户可见的通过或失败结果，以及 Hype 主网公开地址最近 24 小时返回的本品种强平记录。金额触线或仓位消失均不足以证明平台已结算。模拟记录可在同一区域展开。

交易版当前支持 BTC、ETH、SOL 的原生币线性 1:1 合约及主钱包的双边新开或同向加仓。黄金、指数、自定义品种可继续试算。Vest 的考核及 Live Funded 账户未开放 API 交易，本工具使用已打开的官网表单。[Vest 账户限制](https://docs.vestmarkets.com/vest-capital/overview#requirements-and-limits) · [Vest 合约规格](https://docs.vestmarkets.com/platform/perpetual-contract-specifications) · [Hyperliquid 账户事件](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/websocket/subscriptions)

## 启动

安装 Node.js 22 或更高版本。在本仓库内执行一条命令。

```sh
npm start
```

浏览器打开 [本地工作台](http://127.0.0.1:4178)。macOS 也可双击 [打开匹配器.command](打开匹配器.command)。服务仅监听本机回环地址。程序使用浏览器及 Node.js 自带模块，无需安装 npm 依赖。

## 自动识别 Vest Markets

- 在顶部打开「自动识别 VS」，填入交易页地址（例如 `https://next.vestmarkets.com/trade/BTC-PERP`），点「开始自动识别」。公开报价直接订阅 Vest 的盘口和标记价，并从该精确合约的公开规格取得实际报价币用于本次估值；默认 BTC 案例也可[直接启动公开识别](http://127.0.0.1:4178/?vest=BTC-PERP#feeds)。已启用的公开报价在同一品种实时模式下刷新看板会恢复。「停止识别」、切换品种或冻结会结束订阅。
- 需要同步余额和持仓时，在同一 Chrome 或 Edge 配置的扩展管理页开启开发者模式，选择「加载已解压的扩展程序」，加载本仓库的 [extension](extension) 文件夹。刷新 VS 交易页与匹配器，在已经登录的 VS 页面展开账户概览、持仓，再在匹配器点「开始自动识别」。仅同步可见且能区分含义的字段；匹配器会提示未识别的部分。若有多个同品种交易标签页，请保留要识别的一个。用户点击停止、关闭匹配器或切换合约后，当前页面授权结束。
- 公开源和网页源各自保留观察时刻。勾选公开行情时，盘口和标记来自同一 Vest 市场，账户来自页面；取消勾选可单独检验页面读数。缺少有效合约规格、行情过期或缺字段时，看板显示原因。没有账户页数据时，余额显示本地账本来源。自动识别不会写入模拟流水。

## 美元汇率

实时模式默认从美元现货盘口读取 USDC/USD 与 USDT/USD，采用买一、卖一的中间价。行情页「品种映射及汇率」逐币显示汇率、交易所和来源时间。BTC-PERP 公开合约返回 USDC 后，实时 VS 报价轴使用 USDC；Hype 的报价币和结算币分别换算。无歧义的美元金额直接按 USD 计值。离线品种模板独立保留。

每种汇率使用交易所时间和页面设置的过期阈值。HTTP 请求重试不会更新旧数据时间；价格换算依赖的任一币种过期或缺失，匹配即停用。若需自行填写其他币种，可以选择「手动确认」，填入每币折合的美元值，再点「确认手动汇率」。保存平台设置不会给旧汇率续期。报价币识别与本金、合约乘数、结算条款和标的映射的核对相互独立。[Bitstamp 盘口接口](https://www.bitstamp.net/api/#tag/Market-info/operation/GetOrderBook)

## 从一次试算开始

1. 初次打开会读取 Hype 主网行情。要先跑内置案例，在顶部选「离线模拟」；之后会沿用所选模式。选 BTC、ETH、SOL、黄金或 US100，或添加自定义品种。进入「合约规格」查看价格轴单位、两边各自的合约代码、币种、汇率、乘数、点差、数量和价格步长、费率、杠杆及交易状态。「账户与规则」可编辑所有考核门槛和 Hype 强平来源，也能载入[示例规则](config/example.json)。
2. 先看中间的可行区间，再看左右卡片的总上限、剩余可增开额度和候选实际占用。自动模式按资金、失败回本、过关安全和续航的顺序评估离散候选。无可行解时保留不交易，并显示淘汰原因。可筛方向、改排序，或固定一边，输入/拖动另一边金额。「求解另一边」会在固定仓位的约束下重新搜索。
3. 三个情景展示在所设盘口、滑点和基差余量下的条件结果。固定一个方案后改变仓位，就能比较差额、失败结算、达标现金和强平缓冲。展开末尾区域可按多个首次出金目标比较。只有在重置后的现金和盘口下找到下一阶段可行仓位，当前候选才取得续航标记。
4. 去「账本与回放」明确确认模拟开仓、增减、平仓、日内结转、阶段结算或首次提款。编辑金额、接收报价、选择情景和播放 K 线均不会自动入账。外部只读快照与模拟账户不同步时，可先手动「以当前看板建立模拟起点」，再用「看板跟随本地模拟账本」查看后续现金变化。

## 只读数据

- **Hyperliquid** 使用公开 `/info`。可选择主网、测试网或自定义 HTTPS/本机端点，分别读取 `metaAndAssetCtxs`、`l2Book` 和可选公开地址的 `clearinghouseState`。按精确 DEX 与代码映射，包括 HIP-3；预设的黄金和纳指名称不能作为挂牌或共同基准的证明。盘口深度取前五档，超过可见深度的成交不作可行解。[永续合约接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint/perpetuals) · [盘口接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint)
- **VS 手工补录** 可粘贴账户概览、仓位表、报价文字或 JSON。核对解析出的数量、方向、阶段、时间与开市状态后，再确认更新。手工账户金额采用 USD 等值。只给价格的快照不能代替缺失的余额、持仓或保证金记录。
- **本机采集** 在行情页输入 VS 网页的实际 HTTPS 来源进行临时配对。先在 VS 页面框选所需的公开报价或自己的账户概览，再手动运行本地生成的脚本；脚本展示待发字段，确认后发送到本机 `POST /api/vs-snapshot`。页面的 CSP 或浏览器本地网络权限可能阻止发送，此时仍可使用粘贴框。配对绑定来源和品种，支持撤销。
- **时效和冻结** 可选择 1、2、5 秒轮询，并单独设置报价有效期。盘口有交易所毫秒时间戳；上游没有给独立时间戳的上下文读数按接收时间展示。遇到断连、超龄、未挂牌、休市、汇率缺失或映射未确认，工作台停止给出可交易判断。未填地址时，Hype 余额取本地账本。主网与测试网的本机转发只允许已列出的公开信息请求，自定义端点必须允许浏览器跨源读取。

## 账务与风险口径

- 初始个人本金 500 U 含 91 U 报名费。新购后现金 409 U，VS 独立虚拟余额为 10,000 U。两份账本分别计费、计值、画曲线。保证金是占用，开平仓费是支出。已经体现在现金内的报名费、亏损或费用不会二次加入回本门槛。另有未入账的历史成本时，填写「待回收外部成本」。
- 默认考核可结算净值达到 12,000 U 过关，固定失败线为 9,400 U。模拟结清遗留仓位及费用后，VS 重置至 10,000 U，个人现金和已发生费用保留。出金阶段固定失败线为 8,000 U，首次分成为 `0.8 × max(可结算余额 − 10,000, 0)`。默认演示目标为 11,000 U，可按该账户的实际提款条件修改。到账前分成不计可开仓现金，本轮在首次模拟提款到账时结束。
- 按实际成交数量和本地价格变化计算线性盈亏，再用结算币汇率换为 USD。美元仓位按各自步长取整，用可成交买卖价和多档 VWAP 重新验算；已有持仓只对本次成交差额收取费用。直接使用 bid/ask 造成的价差损耗已体现在成交价格内。VS 的费用不从 Hype 现金扣款。
- `quoteScale` 表示本地一个报价单位对应的原生标的数量，`ratio` 表示原生价格变动一个单位时该合约报价的变动。两者通过报价币汇率交叉校验。例如 USD/克与 USD/金衡盎司映射时，每克约为 0.0321507466 金衡盎司；每张合约的乘数仍独立设置。
- 全仓与逐仓分别核算。手工强平参考价需同时匹配净持仓、均价、模式、抵押额和采集时刻；旧指纹不适用时仅能转用可验证档位。强平按连续标记价估算，显示本地 Hype 轴和统一原生价格轴的对应值。海外真实账户的档位、抵押币及附加规则需本人核实。[维持保证金档位](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margin-tiers) · [强平规则](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations)
- 盘口推演保持可见五档的数量形状，移动价格并加入设定的平仓滑点、基差余量。费率、可提现金额、保证金和资金费率均可能改变。端点推演没有持仓时长，界面展示当前资金费率，现金结果未包含未知的未来资金费。排序只比较已搜索且通过全部本阶段硬性条件的仓位，不提供价格预测或胜率。

## 回放和保存

[多品种测试 K 线](fixtures/multi-asset-candles.csv) 使用 `time,asset,open,high,low,close` 格式。可导入 CSV 或用内置考核失败、通过、首次出金、出金号爆号、日内收盘、同柱冲突样例。回放从当前模拟账本的副本出发，按先触及的阈值结算。单根 K 线无法唯一确定顺序时，显示各可能分支与最坏结果并停止。多品种价格路径只能验证输入中实际给出的变化。多日比较展示空仓、停止、重买和重复开平仓的独立结果。

同源浏览器本地存储保存品种、规则和双账本，记账用 Web Locks 协调同源标签页。使用固定的主机名与端口。旧版未释放的模拟占用仍冻结现金，可在账本页释放。旧版合约缺少的保证金档位需核实后补入。导出 [CSV 流水样例](fixtures/ledger-example.csv) 或 [JSON 账本样例](fixtures/ledger-example.json) 对应的文件，可审计交易或在账本页恢复。品种与规则可在同页独立导出或合并恢复。公开地址和桥接配对凭据只在当前会话使用。

## 验证和源码

```sh
npm test
npm run test:browser
npm run test:vest
npm run test:verdict
npm run test:trade
```

`test:verdict` 在 Chrome 逐帧检查连续报价时的结论栏、价格轴及候选表，并验证停流过期和恢复。

浏览器测试启动真实的本地服务和独立临时 Chrome 配置。可通过 `CHROME_BIN` 指定 Chrome/Chromium 路径。该测试需要 Hyperliquid 主网可达，使用公共测试地址检查账户接口；随后在浏览器注入请求超时，以验证断连与超龄。设置 `QA_REPORT_PATH` 可将此次运行的实际报价和通过项目写为 JSON。测试不会使用日常浏览器的配置或账本。

- `src/decision.js` 负责容量、差额成交、费用、反解、风险与搜索。市场与账户的输入校验分别在 `src/engine.js`、`src/feeds.js` 和 `src/workspace-state.js`。
- `src/simulation.js` 与 `src/replay.js` 管理双账本、结算及逐柱回放。`src/feed-ui.js`、`src/vs-parser.js`、`scripts/bridge.js` 提供只读接入。
