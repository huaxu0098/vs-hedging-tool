# VS × Hype 多品种动态对冲匹配器

输入 VS 和 Hype 各自的美元开仓名义额，查看实际可下单数量、标的每变化一个单位时两侧的美元盈亏，以及 VS 通过线和 Hype 强平线之间的距离。可从 BTC、ETH、SOL、黄金（XAU/USD）和纳指 100（US100）开始，也可在「新增自定义品种」中填写合约参数。

## 本地运行

安装 Node.js 22 或更高版本后，macOS 可双击[打开匹配器.command](打开匹配器.command)。也可在仓库目录执行以下命令。项目仅使用 Node.js 和浏览器自带的模块。

```sh
npm start
```

浏览器打开 [本地匹配器](http://127.0.0.1:4178)。在终端按 Ctrl+C 停止服务。运行全部计算与账本测试使用 `npm test`。

## 模拟条件

五个模板的合约代码、报价、点差、费率、VS 门槛和保证金参数均为可编辑的合成数据。工具在本地运行，与交易平台无连接。「合约参数」中可分别指定两侧的报价时间、开市状态、共同基准和线性价格映射。核验基于填写的资料及基差上限。两边任一报价过期、市场休市、基准不匹配、缺少汇率或合约类型不受支持时，界面会显示原因并阻止记账。

模板报价默认有效 900 秒。「重放模拟报价」用于在当前时间重新使用这组模拟价格。工作台的方向和名义额决定当前候选。两侧固定单边费率、完整买卖点差、杠杆和维持保证金率在本次模拟中保持恒定。

## 两份合约如何比较

1. 每侧从自己的中间价加减半个点差得到买卖报价，再按最小价格变动取可成交价。买入向上取，卖出向下取。将美元名义额换算为该侧仓位，按数量步长向下取整，并检查最小下单量。
2. 合约乘数表示每一单位仓位在本地报价变动一点时产生的结算币盈亏。每个原生价格单位对应的美元盈亏为 `方向符号 × 实际数量 × 合约乘数 × 结算币美元汇率 × 价格映射系数`。多头取正，空头取负。两侧敏感度绝对值取小值除以大值得到匹配度，两侧带符号敏感度相加得到净敞口。
3. VS 用实际数量、买卖点差和双边手续费，分别求出首次能达到净盈利门槛的参考价，以及越过后触发净亏损门槛的边界。VS 多头在参考价低于失败边界时触发，空头在高于时触发。若 VS 先触及自身的逐仓维持线，候选也会被拦截。Hype 用初始逐仓保证金和未实现盈亏计算权益，求出权益首次触及维持保证金的连续标记价格。计算采用单档维持率，覆盖当前模拟仓位。真实平台的标记价格、风险档位与资金费影响可查阅 [Hyperliquid 强平规则](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations)。
4. 三条价格线都换算回共同标的轴。VS 多头的缓冲为「Hype 强平价 − VS 通过价」，VS 空头则为「VS 通过价 − Hype 强平价」。缓冲百分比等于带方向缓冲除以当前参考价再乘以 100%。只有强平线在通过线以外、缓冲达到门槛且实际仓位通过其余检查时，才能记录模拟占用。

### 报价币与结算币

每侧的 `quoteUsd` 和 `settleUsd` 分别表示一单位报价币和结算币值多少美元。中间价、点差和价格步长使用本地报价单位，合约乘数使用结算币计量。`ratio` 表示共同标的价格每变动一个原生单位时，该侧报价变动多少。两种币种及其汇率都需填写。

`quoteScale` 表示一个本地报价单位覆盖多少个标的原生单位，默认值为 1。引擎用 `ratio × quoteUsd` 与 `quoteScale` 交叉校验，允许 0.01% 的相对偏差，并检查同币种汇率和映射后的基差。

例如共同参考价每 BTC 为 100,000 USD，某侧报价为 80,000 EUR，1 EUR = 1.25 USD，对应的价格映射系数为 0.8。若一单位仓位每变动 1 EUR 支付 0.8 GBP，且 1 GBP = 1.5625 USD，则一单位仓位对应的美元敏感度绝对值为 `0.8 × 1.5625 × 0.8 = 1`。报价币换算已经体现在映射系数中。

黄金也可在两侧分别按盎司和克计价。共同原生单位取金衡盎司，1 金衡盎司为 31.1034768 克。美元/盎司一侧填 `quoteScale = ratio = 1`。美元/克一侧填 `quoteScale = ratio ≈ 0.03215074657`，因为 1 克黄金只占一金衡盎司的这部分份额。在这组参数下，参考金价每盎司涨 1 美元，每克报价随之涨约 0.03215075 美元。数量步长、结算币和每本地报价点的合约乘数仍按各自合约填写。[NIST 计量单位换算表](https://nvlpubs.nist.gov/nistpubs/Legacy/MP/nbsmiscellaneouspub286.pdf)

## 共享本金与资金流水

模拟账本从 **500 U** 开始，1 U 按 1 USD 等值记账。每次记录都重新核验当前报价与可用余额，为 Hype 侧预留逐仓初始保证金和模拟价格区间内的开平仓费用。VS 考核账户单独计算。切换品种共用同一余额，每条流水保存品种、方向、两侧实际数量和占用金额。「释放」将原预留金额归还可用余额，只表示撤销模拟占用。账本不产生已实现收益。

数据保存在当前浏览器的本地存储中。同一浏览器配置下、同一协议、主机及端口的各标签页共享账本，写入时使用 Web Locks 排他锁。请固定使用上面的本地地址，换端口或浏览器配置会使用另一份存储。清理站点数据会移除本地记录。浏览器无法锁定账本或账本损坏时会停止记账，并显示错误。

## 可复现验收

使用未修改的模板，选择「VS 多 / Hype 空」，两侧开仓金额各填 **2,000 USD**。保持本金至少有一笔候选所需的可用额度，单纯切换和查看结果不会占用资金。以下数字依次给出两侧实际数量、三条触发线和强平缓冲。

- **BTC** 的 VS 为 0.01999 BTC，Hype 为 0.02000 BTC。VS 通过价 103,044.5，跌破 97,040 时失败，Hype 强平价约 109,452.19。缓冲约 6,407.69 美元，约 6.41%。
- **黄金**的 VS 为 0.0079 手，每手乘数 100。Hype 为 0.8 盎司，乘数 1。金价每盎司上涨 1 美元，两侧分别盈亏 +0.79、−0.80 美元。VS 通过价 2,577.40，跌破 2,425.50 时失败，Hype 强平价约 2,736.26。缓冲约 158.86 美元/盎司，约 6.35%。
- **US100** 的 VS 为 0.0199 手，每手乘数 5。Hype 为 0.1 张，乘数 1。指数每上涨 1 点，两侧分别盈亏 +0.0995、−0.10 美元。VS 通过价 20,612.25，跌破 19,406.00 时失败，Hype 强平价约 21,890.33。缓冲约 1,278.08 点，约 6.39%。

**取整导致缓冲不足的反例。** 选黄金，保持上述金额和方向，在「合约参数」中将「最小强平缓冲」设为 **159.30**。默认 VS 数量步长为 0.0001 手，实际缓冲约 158.86，工作台应显示「取整后强平缓冲不足」。仅将 VS 数量步长细化为 0.0000001 手，重新计算得到约 159.76，可通过此门槛。再次使用初始黄金模板数据时，将最小缓冲设回 25、VS 数量步长设回 0.0001 手。
