# VS × Hyperliquid 实时双平台动态对冲计算系统

首页默认使用预设资金和双边实时盘口，确认规划起点后即可查看 VS 与 Hype 的目标方向、数量、实际比例、第二优仓位，以及先触及 VS 失败线或成功线时的结算现金。初始规划取 VS 权益 10,000 U，个人本金 500 U，报名费 91 U，Hype 起始资金为 409 U。AUTO 自动读取 Hype 合约上限及风险档位，联合求解双边仓位、比例和候选杠杆。规划的全仓、空仓且无挂单条件需显式确认。出金阶段的 Hype 起始结余单独填写，初值沿用此前指定的 101.50 U。

切换「资金来源」到「当前账户快照」可使用手工录入、VS 只读桥接或 Hype 公开地址。权益、持仓与可用保证金分别检查确认时间。快速空仓按钮会同时确认两个账户均为全仓、空仓且无挂单。只知道某个合约空仓时，单独填该合约数量 0。个人保护资金和 Hype 可用抵押品在首页分别列出来源。规划参数与实际快照独立保存。

## 本地启动

已安装依赖的 T9 工程可直接运行下列命令，或双击「打开匹配器.command」。服务绑定本机。新检出需要 Node.js 22 或更高版本，先运行 `npm ci`。

```sh
cd /Volumes/T9/CodexData/projects/ChatGPT/gpt/projects/vs-hedging-tool && npm start -- --open
```

服务已启动时直接[打开实时计算首页](http://127.0.0.1:4181/)。

## 使用当前账户快照计算

将首页「资金来源」切换为「当前账户快照」后，按以下流程更新。

1. 选择合约和阶段，输入两边当前标记权益。资金统一以 USDC 等值 U 录入。填写失败时要保住的资金 B 和成功时 Hype 至少要保留的资金 R。规则设置中可修改固定失败线、成功参考净值、个人分成、单边费率、额外摩擦预算及本轮收益要求。未连接钱包也会得到资金允许的比例范围。
2. 输入两边**已成交的带符号净数量**，多头为正、空头为负，确认空仓填 0。工具随公开行情或字段变化重新计算。可预览并确认 VS 网页文字或当前双边 JSON。Hype 也可选填主网公开地址，读取账户、当前持仓、容量与挂单。
3. 默认选择「自动联合求解 / 最大可行 PF 仓位」。确认两边可用抵押品、保证金模式、其他占用和挂单后，程序在合法数量步长上比较双边仓位及方向。按 PF 名义额、最差情景个人现金、清算缓冲、较低初始保证金、较低杠杆依次排名。支持固定 VS 和固定 Hype，也支持明确的双边空仓输入。
4. 平台交易完成后同步钱包数据，或确认新的实际快照。现金计算从快照当前权益开始，只在剩余仓位和平仓及拟调整差额上计费。行情刷新、改规则和浏览器预览都不会写入成交。人工快照及规则保存在当前浏览器本地，公开地址是会话输入。

考核阶段没有可提分成。出金阶段分别显示失败端现金、分成到账前现金和条件到账后现金。待到账不计入保证金。C_ref 可留空，此时仍可计算保护下限、现金上限和前向仓位，整轮收益与利润上限单独标为未知。手工权益有同一时点标记价时按最新行情推估，页面分别显示账户来源、确认时间和计算时间。

首页顶部显示各边目标美元额、增减方向和两种触线后的个人资金。可在规则中设置保护本金之外还需收回的历史支出、最低现金留存与最低强平价格距离。已体现在当前现金快照中的报名费和往期交易费用不会再次扣款。风险卡列出五档 VWAP 相对最优买卖价的滑点、差额手续费和两种终点的平仓费。若搜索无可行调仓，可到达的终点按现仓估算；行情过期或路径提前清算时标出原因。

VS 也可通过“数据连接 → 从 VS 页面只读推送当前快照”配对当前合约。选择来源网页的账户文本，运行当次采集脚本并核对要发往本机的字段，工作台会读取更新。配对凭证十分钟有效，只保存在当前会话。回放测试使用独立开发页和独立内存账本。[本地开发回放页](http://127.0.0.1:4181/dev/replay)

## 自动求解与资金口径

- 首页独立显示个人保护资金、Hype 可用抵押品、到账前 Hype 现金与条件到账后个人资金。在途资金和待到账分成单列。外币可使用有时效的折算；缺少估值时计入的已确认部分为零。
- 设置每边最大保证金占用率、Hype 最低现金留存、强平距离、基差、跳价、Hype 延迟和资金费压力。求解时分别复核数量步长、盘口、实际差额、档位及压力路径。
- 价格/账户过期、阶段到期、资料不全、完整无解和最优仓位保持均有独立状态。后台计算只发布当前快照版本。结果可展开查看前五个已验证仓位、零仓等待及被淘汰方案的缺口。
- 搜索按盘口分段和净现金上界排除不可能胜出的数量区间。完成最优性检查才给出最大仓位结论；触及计算预算时只列本次已验证结果。可见五档深度和已确认的规则限定了搜索范围。
- 两日压力幅度留空仍可求仓位。填写后分别给出多空达到目标需要的 PF 名义额及与最大可行额的比较；超出可见深度只显示买卖一档下界。到期使用当前可见盘口提示待退出现金，实际结算以平台回执为准。

## 行情与验证范围

- Vest BTC、ETH、SOL 使用对应 `-PERP` 的公开 ticker、depth 和 exchangeInfo。Hyperliquid 标记价和档位来自主网 Info，五档盘口优先使用官方 WebSocket 的 l2Book，起始连接和重连时可使用新鲜的 REST 盘口。标记价记录 REST 请求时间，盘口记录交易所事件时间，两者分别检查时效。[官方 WebSocket 订阅](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/websocket/subscriptions)黄金、指数的真实标的和合约映射待核实，仍可先查看资金区间。
- 两边的收益以 USDC 计。Hype 的上述合约按 USDT 报价，1 个本币价格单位的线性盈亏按 USDC 结算。共同价格变动通过 USDC/USD 和 USDT/USD 市场汇率对齐。页面显示现货交易所及时间，也支持有时效的手工汇率。[Hype 合约规格](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/contract-specifications)
- 报价、汇率、账户分别检查时效。公开行情中断保留最近读数，调整量暂停。只有可比对的线性合约使用精确数量计算。默认费率为用户情景；保证金模式、其他持仓与挂单占用、账户实际杠杆或完整规则未核实时，数量只作为条件测算。公开地址接口分开读取持仓和未成交订单，不用可转出金额替代可开仓额度。[只读账户与订单接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint)
- `npm test` 运行数学与业务回归，`npm run test:hedge:browser` 打开隔离的真实 Chrome 并访问主网完成 R 验收，`npm run test:hedge:live` 独立检查 Hype REST 和 WebSocket。真实浏览器验收需要网络；公开金库与手工验算数据均独立于个人账户。原模拟和回放回归可用 `npm run test:hedge:internal` 运行。[开发文档 1.2](docs/vest-hype-dynamic-hedge-codex-spec.md) · [实测报告](docs/current-acceptance.md)

## AUTO 杠杆与清算

每个取整后的 Hype 目标数量都按合约上限和该数量的风险档位枚举整数杠杆。全仓模型按标记价和分档维持保证金率、累进扣除额逐段求清算根，并检查到两条 VS 边界的路径及档位交点。给定相同仓位与抵押权益，各档共享相同的维持保证金与清算风险，分别验算初始保证金、可用抵押品、现金留存和调档前现仓占用。前几项相同且有敞口时，较高的合法档位通常因初始保证金更低而胜出。页面列出各档结果，可核对原因。

当前账户杠杆只从只读 API 展示。规划、当前设置未知或建议调档后尚待平台确认时会标为 `LEVERAGE_UNVERIFIED`。逐仓、未知资金池、缺少可信档位及其他持仓保证金无法核实时，页面保留可计算的资金区间。缺失压力参数时仅给基础条件结果。模型来源见 [保证金模式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margining)、[维持保证金档位](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margin-tiers) 和 [官方清算公式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations)。
