# VS × Hyperliquid 实时双平台动态对冲计算系统

首页显示原生盘口、失败与成功两端现金、四类实际比例区间及仓位明细。表格按比例与 PF 规模区分真实数量网格，一行对应一组方向、数量、成交均价、费用及路径风险。高级详情保留账户录入、分段极值与对账、保证金、杠杆及流水。

自动计算代表方案来自当前仓位优化目标，并标出其所属分段。失败端回收超过保护基准不满或等于 0.01 U 时显示极薄缓冲及缓冲率。高级详情可设置失败回本之外的额外安全缓冲（U），以此约束求解器。统计中的失败回本仍按原保护基准计算。当求解器没有可推荐仓位时，另外标明用于说明两端现金的对照方案。两端净盈利要求两条路径的个人现金均严格超过累计投入。

高级详情中的交集对账采用精确步数分数划分比例段，每段含右端点、下段排除同一点。最低合格点会显示约分后的 h、方向和实际数量。相邻仓位表保持代表方案的 PF 数量和方向，自动列出最近的合法 Hype 数量；在固定 Hype 模式下比较相邻 PF 数量。表中可以看到多一档或少一档时，哪条现金门槛或强平约束先失效。资金理论界限与逐仓实际区间分列，变化说明比较前后两份已完成快照。运行 `CURRENT_URL=http://127.0.0.1:4181 npm run test:hedge:dyn` 可复验 DYN 数值测试及真实浏览器中的资金修改。

Funded 阶段自动显示目标可分金额、全额到账条件现金与已确认收款。实际到账金额只作为收款账户现有余额的明细，首笔分成确认后本轮结束。截止价格未知时显示“到期结果未知”。若设置了截止时间与该品种的明确终点价格，系统按直达该价格的路径计算平仓费用，并检查是否先触及 PF 边界。费用账本、规则与杠杆档位可在详情中核查。

初始规划取 VS 权益 10,000 U，个人本金 500 U，报名费 91 U，Hype 起始资金为 409 U。AUTO 自动读取 Hype 合约上限及风险档位，联合求解双边仓位、比例和候选杠杆。首次打开采用双边全仓、空仓、无挂单的规划假设。已保存的规划设置优先，真实账户持仓仍需有效快照。出金阶段的 Hype 起始结余单独填写，初值沿用此前指定的 101.50 U。

切换「资金来源」到「当前账户快照」可使用手工录入、VS 只读桥接或 Hype 公开地址。权益、持仓与可用保证金分别检查确认时间。快速空仓按钮会同时确认两个账户均为全仓、空仓且无挂单。只知道某个合约空仓时，单独填该合约数量 0。高级详情分别列出个人保护资金和 Hype 可用抵押品的来源。规划参数与实际快照独立保存。

Vest 合约缺字段时，打开「高级详情 → Vest 合约规格与手工确认」，可逐项查看来源并保存已核对的报价币、结算币、下单单位及乘数。整份接口不可用时，页面会列出仓位计算还需要的数量精度和保证金规则。本机确认按合约保存，可撤销。断线或规格冲突期间，首页保留同品种、资金模式、账户及阶段的上次完整结果，显示历史时间。首次使用且没有历史时，页面显示具体缺项；已收到的原生行情独立展示。此流程可用 `CURRENT_URL=http://127.0.0.1:4181 npm run test:hedge:vest` 在独立 Chrome 中复验。

标准 BTC 永续与页面连续换帧可用 `CURRENT_URL=http://127.0.0.1:4181 npm run test:hedge:perp` 实测。该命令在独立 Chrome 中打开官方交易页和本地工作台，按 Mark、Oracle 及同源时间的 L2 对照，并连续观察至少 60 秒，核查结果闪白、节点重挂、过期请求、每段现金和风险。

## 使用当前账户快照计算

将「高级详情」中的「资金来源」切换为「当前账户快照」后，按以下流程更新。

1. 选择合约和阶段，输入两边当前标记权益。资金统一以 USDC 等值 U 录入。分别填写失败保护基准 B、成功平仓后 Hype 最低权益 R_success、开仓后最低可用抵押品 R_free。旧版 R 自动迁移至 R_success，R_free 初值为 0 U。净利润另按含已付报名费和外部投入的个人总投入，加上另行待收回的历史成本为基准。当前账户缺少总投入时仍可计算保护与留存。规则设置中可修改固定失败线、成功参考净值、个人分成、单边费率、额外摩擦预算及本轮收益要求。未连接钱包也会得到资金允许的比例范围。
2. 输入两边**已成交的带符号净数量**，多头为正、空头为负，确认空仓填 0。工具随公开行情或字段变化重新计算。可预览并确认 VS 网页文字或当前双边 JSON。Hype 也可选填主网公开地址，读取账户、当前持仓、容量与挂单。
3. 默认选择「自动联合求解 / 最大可行 PF 仓位」。确认两边可用抵押品、保证金模式、其他占用和挂单后，程序在合法数量步长上比较双边仓位及方向。按 PF 名义额、最差情景个人现金、清算缓冲、最低可行杠杆、较低初始保证金依次排名。支持固定 VS 和固定 Hype，也支持明确的双边空仓输入。
4. 平台交易完成后同步钱包数据，或确认新的实际快照。现金计算从快照当前权益开始，只在剩余仓位和平仓及拟调整差额上计费。行情刷新、改规则和浏览器预览都不会写入成交。人工快照及规则保存在当前浏览器本地，公开地址是会话输入。

考核阶段没有可提分成。出金阶段分别显示失败端现金、分成到账前现金和条件到账后现金。待到账不计入保证金。C_ref 可留空，此时仍可计算保护下限、现金上限和前向仓位，整轮收益与利润上限单独标为未知。手工权益有同一时点标记价时按最新行情推估，页面分别显示账户来源、确认时间和计算时间。

首页显示各边目标美元额和两种触线后的个人资金，当前仓位到目标仓位的增减量可在高级详情核对。可在规则中设置保护本金之外还需收回的历史支出、最低现金留存与最低强平价格距离。已体现在当前现金快照中的报名费和往期交易费用不会再次扣款。风险卡列出五档 VWAP 相对最优买卖价的滑点、差额手续费和两种终点的平仓费。若搜索无可行调仓，可到达的终点按现仓估算；行情过期或路径提前清算时标出原因。

VS 也可通过“数据连接 → 从 VS 页面只读推送当前快照”配对当前合约。选择来源网页的账户文本，运行当次采集脚本并核对要发往本机的字段，工作台会读取更新。配对凭证十分钟有效，只保存在当前会话。回放测试使用独立开发页和独立内存账本。[本地开发回放页](http://127.0.0.1:4181/dev/replay)

## 自动求解与资金口径

- 高级详情分列个人保护资金、Hype 可用抵押品、到账前 Hype 现金与条件到账后个人资金。在途资金和待到账分成单列。外币可使用有时效的折算；缺少估值时计入的已确认部分为零。
- 设置每边最大保证金占用率、Hype 最低现金留存、强平距离、基差、跳价、Hype 延迟和资金费压力。求解时分别复核数量步长、盘口、实际差额、档位及压力路径。
- 价格/账户过期、阶段到期、资料不全、完整无解和最优仓位保持均有独立状态。后台计算只发布当前快照版本。结果可展开查看前五个已验证仓位、零仓等待及被淘汰方案的缺口。
- 搜索按盘口分段和净现金上界排除不可能胜出的数量区间。完成最优性检查才给出最大仓位结论；触及计算预算时只列本次已验证结果。可见五档深度和已确认的规则限定了搜索范围。
- 两日压力幅度留空仍可求仓位。填写后分别给出多空达到目标需要的 PF 名义额及与最大可行额的比较；超出可见深度只显示买卖一档下界。到期使用当前可见盘口提示待退出现金，实际结算以平台回执为准。

## 行情与验证范围

- Vest BTC、ETH、SOL 使用对应 `-PERP` 的公开 ticker、depth 和 exchangeInfo。Hyperliquid 标记价和档位来自主网 Info，五档盘口优先使用官方 WebSocket 的 l2Book，起始连接和重连时可使用新鲜的 REST 盘口。标记价记录 REST 请求时间，盘口记录交易所事件时间，两者分别检查时效。[官方 WebSocket 订阅](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/websocket/subscriptions)黄金、指数的真实标的和合约映射待核实，仍可先查看资金区间。
- 工作台以 USDC 为资金账本单位。两侧原生 Mark 与成交盘口分别标注报价币。高级连接详情列出标的、报价币、结算币、乘数、元数据来源、美元现货 Bid/Ask 和源时间。首页分别显示 Vest 的原生买一、卖一与 Mark，以及 Hype 的原生买一、卖一与 Mark。买入消耗卖盘，卖出消耗买盘，按实际调仓数量计算多档成交均价和费用。条件终点按各自盘口深度平移至该终点再反向平仓，未来深度变化会影响实际结算。标准 BTC 永续基础路径按相同原生点数变动，Hype 的每个 USDT 价格点按每 BTC 兑付 1 USDC。稳定币现货汇率仅作高级详情中的独立汇率风险参考。如另行配置外币到账资金，需单独核实其 USDC 估值。
- Vest BTC-PERP 的 `exchangeInfo` 返回 BTC / USDC；官方规格说明 USDC 结算、线性 1:1。Hyperliquid 标准永续 BTC 的 `metaAndAssetCtxs` 提供市场代码和抵押币索引，`spotMeta` 核对结算币。官方规格列明其价格以 USDT 计价，每数值点盈亏按 USDC 1:1 结算。接口直接声明的报价币优先使用；报价或结算币无法核实时显示 `QUOTE_CURRENCY_UNVERIFIED`。必要 FX 超过盘口有效期、断连或无来源时撤回仓位。脱锚报警阈值默认 50 bp，可在资金规则中修改；美元估值偏离独立显示。历史手工无方向汇率不会参与计算。[Vest 合约规格](https://docs.vestmarkets.com/platform/perpetual-contract-specifications) · [Hyperliquid 合约规格](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/contract-specifications)
- 报价、汇率、账户分别检查时效。公开行情中断保留最近读数，调整量暂停。只有可比对的线性合约使用精确数量计算。默认费率为用户情景；保证金模式、其他持仓与挂单占用、账户实际杠杆或完整规则未核实时，数量只作为条件测算。公开地址接口分开读取持仓和未成交订单，不用可转出金额替代可开仓额度。[只读账户与订单接口](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint)
- `npm test` 运行数学与业务回归，`npm run test:hedge:browser` 打开隔离的真实 Chrome 并访问主网完成 R 验收，`npm run test:hedge:live` 独立检查 Hype REST 和 WebSocket。真实浏览器验收需要网络；公开金库与手工验算数据均独立于个人账户。原模拟和回放回归可用 `npm run test:hedge:internal` 运行。[开发文档 1.2](docs/vest-hype-dynamic-hedge-codex-spec.md) · [实测报告](docs/current-acceptance.md)

## 资金规则驱动的 AUTO 求解

输入个人保护本金（内含已支付的报名费）、本金之外另需收回的成本、已到账外部资金、Hype 权益及可用抵押品、PF 当前权益及失败线和目标净值，再设成功端 Hype 留存。确认当前仓位和挂单后自动重算。空仓用明确的零，当前账户与开考前规划分别保存。实时行情或资金规则变化后，旧调整量立即失效。规划中若保护本金与起始本金相等，编辑起始本金会同步更新保护本金；单独设置不同的保护目标后两者分别保留。

设目标保护额为 B，Hype 当前权益为 H，外部已到账资金为 E，成功端要求留存 R。基础保护下限是 max(0, (B − H − E + 失败端额外预算) ÷ PF 到失败线的净值距离)，基础留存上限是 (H − R − 成功端额外预算) ÷ PF 到成功线的净值距离。到账前的检查只使用 Hype 自身权益。已支付费用保留在当前余额中，同一笔费用只计一次。

在双平台可成交数量网格上，每个候选取共同价格因子变化时的损益敏感度绝对值之比 h。程序按已有仓位到目标仓位的差额调仓，逐档计算成交，分别反解两个 PF 净结算边界。对每条路径，用实际 Hype 成交成本加上 h 倍 PF 成交成本，替换基础公式中的预算，并纳入另设终点摩擦。PF 成本通过改变触线距离影响 Hype 盈亏。在高级详情中可核对资金公式与逐笔现金桥接；现金、盘口、保证金和清算约束共同决定可保留的候选与最低可行杠杆。失败端的外部资金、PF 模拟权益及成功端尚未到账分成均不进入 Hype 抵押品。

运行 `CURRENT_URL=http://127.0.0.1:4181 npm run test:hedge:ranges` 可复核 AUTOSEL、RANGE 和 PATH 用例，并在 Chrome 检查工作台的双路径现金、分桶、自动代表方案、完整分段、行情刷新和 Funded 到账口径。

`node --test tests/hedge-funding-formula.test.js` 运行 FORM01—FORM12。`CURRENT_URL=http://127.0.0.1:4181 npm run test:hedge:funding` 加验 Chrome 上单独修改本金、留存和失败线产生的新结果。

## 实际仓位、三种优先目标与时间校验

首页展示三个条件目标，分别最大化合格 PF 规模、失败回收缓冲和成功后 Hype 留存。重合的目标仍逐项显示；使用预设资金时标明空仓假设。同方向、同一精确比例的大小目标可以展开并列核对，扩仓差额按两组各自核算的数量、现金、保证金和强平距离相减。完整分页在“高级详情 → 完整目标仓位网格与分页”。交集比例段包含精确上下界，前后两段分别严格小于下界、大于上界。归段、计数及分页共用整数数量步长；在闭区间内仍须逐仓通过双方风控、失败本金加缓冲及成功最低留存门槛。无交集时完整合法网格仍可查阅。

失败回收比较个人资金与保护本金，成功留存比较 Hype 平仓权益与最低留存。初始保证金仅占用抵押品，外部到账资金只参与个人现金核算。逐笔流水、分段对账及清算模型均在高级详情中。

时间差阈值可在规则设置中修改，初值为双边盘口及标记时间差 3 秒、账户字段时间差 120 秒。价格、标记和账户字段各自还须满足有效期。行情到达先更新报价，后台 Worker 对完整合法网格按解析边界重估。普通盘口和数量变化合并至距上次派发 1.8 秒；同平台标记价、买一或卖一明显变化时最短间隔 0.4 秒。配置和资金变更立即派发，重复数值观测只更新来源时间。首页统一显示当前数据状态及最近成功计算时间。计算期间保留上帧仓位与现金，整份报告完成后一次替换。数据过期或超时单独标为暂停，资金来源及品种各自隔离。考核倒计时取自手工确认的实际截止时间。迟滞默认 2 个各平台数量步长，填 0 可关闭。旧目标须重新通过本帧所有已配置的风控条件，原始求解差额与迟滞后的建议差额分别展示。

全仓清算采用分档解析式与独立的数值求根交叉核对。后者重新按盘口计算调仓成交影响及费用，分段累计维持要求，再求权益跌至维持要求的交点。账户数据齐备时额外核对同一快照的全仓维持要求和现仓平台参考价，容差分别为 0.01 U 和快照标记价的 1 基点。未成交目标只有模型估值。预设、组合仓位不完整及参考值未核实时，页面标为条件估算。

## AUTO 杠杆与清算

每个取整后的 Hype 目标数量都按合约上限和该数量的风险档位枚举整数杠杆。全仓模型按标记价和分档维持保证金率、累进扣除额逐段求清算根，并检查到两条 VS 边界的路径及档位交点。给定相同仓位与抵押权益，各档共享相同的维持保证金与清算风险，分别验算初始保证金、可用抵押品、现金留存和调档前现仓占用。这些条件相同时选第一个可行档位。页面显示低一档的约束缺口、提高杠杆可释放的初始保证金，以及表内各实际仓位的保证金与清算距离。每次计算附行情、账户和规则输入标识，可在首页展开核对。

当前账户杠杆只从只读 API 展示。规划、当前设置未知或建议调档后尚待平台确认时会标为 `LEVERAGE_UNVERIFIED`。逐仓、未知资金池、缺少可信档位及其他持仓保证金无法核实时，页面保留可计算的资金区间。缺失压力参数时仅给基础条件结果。模型来源见 [保证金模式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margining)、[维持保证金档位](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/margin-tiers) 和 [官方清算公式](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/liquidations)。
