# 开发任务：VS × Hype 实时行情对接与双平台仓位匹配可视化系统

---

## 1. 核心目标与业务定位

构建一个连接 **VS（Prop Firm 考核/出金账户）** 与 **Hype（Hyperliquid 永续合约账户）** 的跨平台动态对冲与仓位匹配决策系统：
1. **自动行情与账户感知**：自动对接 Hype 公开 API 实时查询标的价格与盘口深度（并支持填入只读钱包地址同步 Hype 余额与持仓）；支持通过“VS 页面文本智能识别解析 / 本地采集推送 / 手动微调”获取 VS 页面实时报价与账户余额。
2. **双平台余额与可开仓位全景匹配**：在可视化页面中直观识别并对比双方平台当前剩余可用余额、已占用保证金，以及各自在杠杆、步长和风控约束下的**最大可开仓位（美元名义额与真实手数/币数）**，自动计算双边交集与最优对冲匹配方案。
3. **严格决策顺序与风险约束**：主要用途为日内决策匹配与风险推演，不预测未来价格。所有匹配候选必须严格按以下顺序过滤与评估：
   - **① 个人资金约束**：个人总现金与双边保证金是否足以开仓并抗住波动；
   - **② VS 失败兜底**：当价格触及 VS 失败线时，Hype 盈利平仓后能否完整收回报名费及历史累计成本；
   - **③ VS 过关安全**：当价格触及 VS 通过线/目标出金线时，Hype 反向仓位能否在全过程中不被强平并保留安全价格缓冲；
   - **④ 过关后续航**：考过并重置 VS 后，个人剩余现金是否足以支撑后续继续操作直至首次出金。
   - **硬性底线**：无可行匹配就不交易；若只满足其中单一方向，必须明确标注原因并警告，严禁把历史示例中的固定比例（如 10%、16%、50%）、固定金额（如每次 1,000U）、固定点差或轮次上限硬编码为策略。

## 2. 默认账户模型（所有参数支持页面可编辑）

- **个人总本金**：默认 `500U`（已包含 `91U` 报名费）。新购考核号支付报名费后，Hype 初始可用现金为 `409U`；VS 的虚拟/模拟资金严禁作为 Hype 的保证金抵押。
- **考核阶段（Challenge）**：VS 初始净值 `10,000U`；扣除交易费用后的可结算净值达到 `12,000U` 视为通过；固定失败线 `9,400U`（默认固定回撤，严禁与追踪回撤混淆）。考核阶段盈利不可提款。
- **过关结算机制**：VS 达标过关时，系统执行或模拟关闭/结算遗留对冲仓位并扣除对应平仓费用；随后 **VS 净值重置为 `10,000U`**，而 **Hype 现金余额、已实现盈亏及历史累计成本费用均不重置**。明确区分“考核过关取得出金号”与“实际提款现金到账”。
- **出金阶段（Funded）**：固定失败线 `8,000U`，无强制盈利目标。首次提款可分金额公式为：`80% × max(可结算净余额 - 10,000U, 0)`。例如：净值跌至 `9,000U` 后回升至 `9,800U` 时不可提款（为 `0`）；余额达到 `10,200U` 时可分 `160U`。首次目标出金点由用户自由设定（`11,000U` 仅为默认演示值，支持多出金点横向对比）。未到账分成不计入当前个人现金或可用保证金；首次出金结算后本轮周期结束，不凭空假定后续提款规则。
- **费率与结算假设**：VS 默认单边费率 `0.01%`（万一），Hype 默认单边费率 `0.05%`（万五）；每笔实际开仓、增减仓、平仓均按成交名义价值单独计费。触线判定支持切换“按标记净值触线”或“按平仓可结算净值触线”，默认演示严格以扣除成交成本后的净结算额计算通过与提款。所有平台未明示规则均需在界面标注为“模拟假设”。

## 3. Hype API 自动对接与 VS 页面数据识别接入

### 3.1 Hype 端公开 API 自动查询（严格只读安全架构）
- **安全红线**：系统严格保持**只读（Read-Only）**，绝不读取、存储或索要任何私钥（Private Key）或 API 交易签名密钥，绝不实现任何实盘下单、撤单或划转接口。
- **实时行情与盘口自动拉取**：
  - 默认对接 Hyperliquid 公开接口（如 `POST https://api.hyperliquid.xyz/info` 或 WebSocket `wss://api.hyperliquid.xyz/ws`，支持用户在设置中自定义 API Endpoint 以适配主网、测试网或本地代理），提供“实时自动轮询（1s/2s/5s 可调）”与“离线/手动冻结”一键切换。
  - 调用 `metaAndAssetCtxs` 自动获取对应标的的 **标记价（Mark Price）、资金费率（Funding Rate）、最大杠杆倍数、数量步长（szDecimals）**；调用 `l2Book` 实时获取 **买一价（Best Bid）、卖一价（Best Ask）及前五档盘口深度**，用于估算真实吃单滑点。
  - **品种映射与未挂牌保护**：支持配置 VS 品种到 Hype 合约代码（含永续主网及 HIP-3 映射标的）的映射表；若某品种在 Hype API 中不存在或未挂牌，自动标注“Hype 未挂牌/需手动输入报价”，绝不张冠李戴。
- **Hype 账户余额与持仓只读同步（可选填公开地址）**：
  - 支持用户填入 Hype 公开钱包地址（`0x...`，无需私钥），通过 `clearinghouseState` 接口自动读取 Hype 当前 **账户总净值（Account Value）、剩余可用保证金（Available/Withdrawable Margin）、已占用保证金（Margin Used）、当前各品种持仓数量/开仓均价/未实现盈亏及接口参考强平价**；未填地址时使用可编辑的本地账户状态（默认 `409U`）。
- **行情新鲜度熔断**：每条价格均附带毫秒级时间戳与延迟显示；若 API 断连或报价超过用户设定的过期阈值（如 `5秒`），界面立即触发“报价过期”告警，**自动锁定禁止显示“可交易/通过”结论**。

### 3.2 VS 页面数据智能识别与实时比对
由于 VS（Prop Firm）网页端通常无公开免签 API，系统提供多通道便捷数据接入，并与 Hype 实时行情进行毫秒级比对：
- **VS 页面文本智能识别解析器（Smart Paste Parser）**：
  - 提供“一键粘贴识别 VS 页面”输入框：用户只需在 VS 交易网页上全选或框选复制账户概览栏与报价栏文本（或粘贴 JSON/表格文本），前端内置结构化规则解析引擎自动提取并识别：
    1. **VS 账户余额 / 净值（Balance / Equity）**
    2. **VS 已用保证金（Used Margin）与剩余可用保证金（Free Margin）**
    3. **当前所处阶段（考核中 / 出金阶段）**
    4. **当前已有持仓（品种、多空方向、手数/数量、开仓均价、浮动盈亏）**
    5. **VS 页面实时报价（买一价 Bid、卖一价 Ask、当前价/标记价）**
  - 解析后展示结构化确认卡片（高亮显示识别出的数值与单位），用户一键确认即可写入当前状态；同时支持随时手工修改任意字段。
- **可选本地浏览器只读采集推送端点（Local Bridge）**：
  - 后端提供本地只读接收接口（如 `POST /api/vs-snapshot`）及一段可复制的浏览器控制台只读读取脚本（供用户在本地浏览器中按需手动读取 VS 页面 DOM 数值并推送至本地匹配器），绝不绕过验证码或触碰下单按钮。
- **跨平台实时价差与成本比对**：
  - 实时计算 `VS 报价 vs Hype API 实时报价` 的绝对价差、百分比基差（Basis）、双边盘口点差总和，并与当前候选仓位的“点差成本预算上限”实时比对，超出预算立即预警。

## 4. 多品种配置与合约规格校验

- **预置与扩展**：内置 **BTC、ETH、SOL、黄金（XAU/USD）、纳指100（US100）** 五大完整模拟模板，并支持用户新增自定义品种。严禁仅因名称相似就默认两边可对冲或已挂牌。
- **双边独立合约规格**：每个品种需独立配置 VS 与 Hype 的：合约代码、标的名称、线性收益类型（非线性/反向合约直接拒绝并提示不支持，严禁套用 BTC 公式）、报价币种与结算币种、必要汇率（如非 USD 计价时的实时换算汇率）、合约乘数/每点价值、最小价格变动步长（Tick Size）、最小数量步长（Lot/Step Size）、最小下单手数、交易时段状态（开盘/休市）、单边手续费率、杠杆及维持保证金参数。
- **步长取整重算**：用户输入目标美元名义价值后，程序严格按各自平台的最小手数与数量步长向下/就近取整，换算为真实成交手数/币数/张数，并**基于取整后的真实数量重新反算全部盈亏、保证金与触线价格**；若取整后导致数量为 `0` 或双边风险敞口严重失衡，直接标记“取整后无解”。
- **敏感度展示**：明确展示标的每波动 `1 美元/币`、`1 美元/盎司` 或 `1 指数点` 时，VS 与 Hype 各自盈亏多少 U（每点价值）。缺汇率、一边休市或合约规格不兼容时，严禁显示“通过”。

## 5. 动态仓位匹配引擎与账务核算核心

1. **当前状态反解触线价格**：
   - 针对多种 VS 候选美元仓位（含“0 仓位/不交易”）及多空方向，在**包含已有持仓、当前非初始余额、已实现盈亏及预扣平仓手续费**的前提下，精确反解出触发 VS 规则的目标价格：
     - 考核阶段：反解**净值达 `12,000U`（扣费后）的通过价**与**触及 `9,400U` 的失败价**；
     - 出金阶段：反解**达到自选目标出金净值的出金价**与**触及 `8,000U` 的失败价**。
   - 同步显示当前报价距离各触线价格还差多少美元/点数、百分比幅度，以及账户净值还差多少净盈亏。
2. **双平台可开仓位计算与反向匹配求解**：
   - 先基于双方当前可用保证金、杠杆倍数、维持保证金率、合约乘数、步长及用户风控上限（最大保证金占用率、最低现金留存、最低强平缓冲），分别算出 **VS 最大可开仓位** 与 **Hype 最大可开仓位**。
   - 对每个 VS 候选仓位，通过枚举或数值求解器在 Hype 的合法可交易区间内搜索反向对冲仓位；比例是匹配计算的结果，不是预设限制（允许匹配比例超出任何历史示例，也允许在资金不足时输出“无解”）。
   - 若账户已有持仓，清晰计算并输出**本次需要增仓或减仓的差额**，不重复计算已有仓位的保证金。
3. **双情景现金与盈亏精算**：
   - **VS 失败价情景**：按两边各自真实可成交价（含买一/卖一及滑点）计算 Hype 平仓盈利并扣除双边平仓费后的最终个人现金，明确回答“距离收回初始 `500U` 本金还差/盈余多少 U（含历史累计未收回成本，报名费仅在首次买号及后续重新买号时扣除）”。
   - **VS 成功/出金价情景**：校验在价格向 VS 盈利方向运行的全过程中，Hype 反向亏损是否会触及强平，以及最终结算平仓后个人还剩多少可用现金。
4. **强平价验证与安全缓冲**：
   - Hype 强平价优先采用当前候选总仓位对应的手工精确输入值或已验证的逐仓/全仓维持保证金档位模型，界面必须清晰标注强平价来源与假设；仓位变动后旧强平价自动作废重算。
   - 定义强平价格缓冲：当“VS 做多 / Hype 做空”时，`价格缓冲 = Hype 强平标记价 - VS 达标时映射出的 Hype 压力标记价`（反向持仓时公式相反）。必须同时验证开仓初始保证金、持仓期维持保证金及最低预留现金。明确区分“账户余额亏光价”与“实际强平价”，正缓冲不等于整体盈利。强平参数缺失时标注“无法验证”，严禁列入推荐。
5. **双账本独立记录与费用明细**：
   - 严格分开记录 **VS 模拟净值账本** 与 **个人真实现金账本**（严禁将两账本余额相加）。
   - 线性标的每笔毛盈亏 = `有符号数量 × 合约乘数 × 价格变动 × 必要汇率`；手续费 = `每笔实际成交名义额 × 单边费率`。若采用真实买一/卖一成交价建模，不再重复扣除点差；若采用中间价/标记价建模，显式计入开平仓半点差。明确区分“保证金占用（可释放）”与“实际交易费用（不可退回）”。提供费用前后对比与逐笔可审计流水明细。
6. **候选筛选、排序与淘汰解释**：
   - 先硬性剔除违反资金、强平缓冲或成本回收约束的候选方案，再按用户偏好（默认优先“保本金与最差情景最优”，亦可按达标剩余现金、强平缓冲或低保证金占用排序）给出推荐。不把终点收益当成确定保证，不凭空编造胜率。
   - 明确为通过筛选的候选打标：**“仅可完成本阶段”** 或 **“可安全续航至首次出金”**；同时必须展示**至少一个被淘汰候选及其具体失败缺口**（如“Hype 差 38U 保证金被提前强平”或“VS 失败时仍缺 24U 才回本”）。
7. **动态点差与滑点成本预算**：
   - 针对每个候选方案单独计算双平台点差与滑点的**总成本预算（U）**、**盈亏平衡点差上限**，以及扣减平仓滑点与基差波动余量后的**安全入场点差提示**，绝不仅凭开仓瞬间点差较小就判定整笔交易盈利。

## 6. 中文可视化页面布局与交互设计

页面全局保持**持续醒目的“模拟推演与决策辅助（非实盘自动下单）”标识**，常态界面以**金额、可用余额、可开仓位与价格距离**为核心，复杂公式与模型假设支持一键折叠/展开：

1. **首屏顶部：模式切换与一句话决策结论栏**
   - 提供 **“自动最优匹配”** 与 **“固定一边手动试算（固定 VS 调 Hype / 固定 Hype 调 VS）”** 两种核心模式，以及 **“Hype API 实时连接 / 离线模拟”** 状态开关。
   - **首屏一句话核心结论**：动态展示当前品种、VS 建议方向及金额（含手数）、Hype 建议反向及金额（含币数）、相对现有持仓的本次增减差额、最终判定状态（**【匹配可交易】 / 【仅单边满足】 / 【不匹配】 / 【无法验证】**）及一句直白原因。
2. **核心新增看板：双平台剩余余额与可开仓位匹配显示面板（三栏全景对比）**
   - **左栏（VS 平台资金与开仓能力卡片）**：
     - 展示 VS 当前净值、距离通过/出金线差额、距离固定失败线缓冲；
     - 醒目展示 **当前已占用保证金** vs **当前剩余可用余额/保证金**；
     - 实时计算并展示按当前价格折算的 **VS 最大可开仓位（美元名义额 & 真实手数）** 以及受风控约束后的 **安全可开仓上限**（已有持仓时清晰区分“总上限”与“剩余可增开额度”）。
   - **右栏（Hype 平台资金与开仓能力卡片，同步 API 状态）**：
     - 展示 Hype 钱包净值（标注 API 实时刷新状态与延迟 ms）、与个人初始本金对比、已占用保证金、**当前剩余可用保证金**、最低现金留存；
     - 实时计算并展示按 Hype 实时盘口价与维持保证金率折算的 **Hype 最大可开仓位（美元名义额 & 真实币数/张数）** 以及留足强平缓冲后的 **安全可开仓上限**。
   - **中栏（跨平台实时报价与可开仓位匹配交集引擎）**：
     - **实时报价对比条**：并排显示 VS 报价 vs Hype API 实时买一/卖一/标记价、实时价差（U/点/百分比）、以及当前点差占本方案“点差成本预算”的进度条（绿/黄/红预警）。
     - **可开仓位匹配漏斗**：直观展示 `VS 可开上限` 与 `Hype 可开上限` 经乘数与汇率对齐取交集后的 **双边实际可匹配仓位区间**，以及当前选中的最优匹配比例与双向保证金占用率。
     - 快捷入口：**“📋 粘贴识别 VS 页面数据”** 弹窗/抽屉，一键解析 VS 网页文本并更新左栏与报价。
3. **中部主图：双平台对齐价格轴与情景推演联动区**
   - **两条垂直/水平对齐的价格标尺**：左侧 VS 价格轴标出当前标记价/买卖价、通过线（`12,000U`）或目标出金线、固定失败线（`9,400U` / `8,000U`）；右侧 Hype 价格轴实时映射并标出 Hype 当前 API 标记价、对应 VS 触线时的 Hype 压力价、以及 **Hype 强平线与安全缓冲区间**（强平参数未知时不画伪精确线，直接显示“强平线未验证”）。
   - **单位严格规范**：币类显示 `美元/币`，黄金显示 `美元/盎司`，指数显示 `点`；双边报价单位不同时自动先做可验证换算再对齐。

4. **底部区域：双账本资金曲线、逐笔明细与 K 线回放台**
   - **独立双曲线图**：展示 **VS 净值曲线**（附带失败线与目标线参考线）与 **个人真实现金曲线**（绝不将两条曲线相加），下方附带双平台保证金占用柱状图及累计费用统计。切换不同交易品种时，共享账户中已有未平仓位占用的保证金必须持续保留，严禁清零。

## 7. 交付物与强制验收标准

请交付完整源码、中文 `README.md`、**一条本地启动命令**、示例配置文件、多品种测试 K 线 CSV、导出流水样例、自动化测试脚本及实际测试运行报告。完成后必须通过真实浏览器启动服务并实测所有核心交互（严禁用静态 HTML 或 mock 截图替代真实功能）。

必须通过以下 **12 项核心验收测试**：
1. **扣费边界**：扣费前净值达标（如 `12,005U`）但扣除双边平仓手续费后低于 `12,000U` 的情况，严禁判定为“通过”；
2. **失败回本对照**：VS 失败线触发时，分别跑通“Hype 净盈利足以覆盖 91U 报名费+历史成本”与“未覆盖导致净亏损”各一例；
3. **强平前置淘汰**：在到达 VS 通过线前 Hype 先触及强平线的仓位组合，必须被自动淘汰并给出具体缺口说明；
4. **过关局部重置**：考核过关执行结算后，仅 VS 净值重置为 `10,000U`，Hype 现金余额与历史累计成本保持延续不重置；
5. **出金线规则**：出金阶段余额跌破 `10,000U`（如 `9,000U`）后回升至 `9,800U`，可提款金额必须严格显示为 `0U`；
6. **单边固定独立性**：固定 VS 仓位仅调整 Hype 仓位时，VS 触线价格保持不变，仅 Hype 强平缓冲与最终个人现金结果变化；
7. **多日空仓 vs 持仓成本**：多日横盘未达标时，空仓等待不产生额外交易手续费，与反复开平仓轮次的累计成本有明显差异；
8. **已有持仓差额调仓**：账户已有未平仓位时，匹配引擎仅输出需要增减的差额数量及对应差额手续费；
9. **缺失强平参数保护**：未提供 Hype 强平价且保证金档位参数不完整时，状态必须显示“无法验证”且不得进入推荐列表；
10. **多品种与共享保证金**：BTC（币）、XAU/USD（黄金）、US100（指数）各跑通一例完整匹配，验证两边合约乘数不同时的数量换算、取整后无解提示，以及多品种同时持仓时账户可用保证金共享扣减、互不重复占用；
11. **K 线同柱冲突处理**：单根 K 线极值同时触及双边触发线且顺序不明时，系统不得输出确定性盈利结论，必须展示不确定提示与最坏情景；
12. **Hype API 联动、报价熔断与 VS 识别看板**：验证成功从 Hype 公开 API 拉取实时行情并刷新右侧余额/可开仓位面板；模拟 API 超时/报价过期时触发“报价过期”熔断锁定；使用一段包含 VS 账户余额、可用保证金、持仓与报价的网页粘贴文本，验证智能识别解析器准确提取并刷新双平台可开仓位匹配结果。
