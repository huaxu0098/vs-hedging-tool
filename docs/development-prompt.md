# VS × Hype 多品种动态对冲匹配器

开发一个本地中文模拟工作台。用户输入两边计划开仓的美元名义金额，系统以可下单的实际数量进行匹配，并在添加模拟占用前重新校验。以下为项目的开发与验收要求。

【多品种支持：BTC 只是示例，不是系统限制】

1. 页面顶部提供「选择品种」和「新增自定义品种」。预置 BTC、ETH、SOL、黄金（XAU/USD）、纳指 100（US100）作为模拟模板，不假设两家平台一定提供同名或相同规格的合约。以后新增品种应只需填写参数，不用改计算代码。

2. 用户仍然只需输入“VS 开多少美元、Hype 开多少美元”。程序负责换算成两边实际的币数、盎司、手数或张数。VS 和 Hype 分别配置合约代码、报价及结算币种、合约乘数或每点价值、最小价格变动、最小下单量、数量步长、费率和保证金规则。按各自步长取整后，必须重新验算，不能用取整前的理想仓位作为结果。

3. 匹配的核心是“标的价格每变化一个单位，两边各盈亏多少美元”，而不是比较表面上的手数。界面按品种显示：
   - BTC、ETH、SOL：币价每涨跌 1 美元，两边分别盈亏多少。
   - 黄金：金价每盎司涨跌 1 美元，两边分别盈亏多少。
   - US100：指数每涨跌 1 点，两边分别盈亏多少。

   所有品种都要计算 VS 通过价、失败价、Hype 强平价以及两条线之间的缓冲。价格距离同时显示该品种的原生单位和百分比。

4. 只自动匹配同一标的且价格关系可验证的合约。名称相似、跟踪基准不同、计价货币无法换算、一边休市或报价过期时，明确显示原因，不得推荐。未实现反向或非线性合约公式时，显示“不支持该合约类型”，不要套用 BTC 线性公式。

5. 切换品种后，输入单位、价格轴、点差、合约参数和候选仓位同步切换；流水按品种区分，但 500U 真实本金共用。不能从 BTC 切换到黄金就把本金重置，也不能把已占用的保证金再用一次。

验收：至少用 BTC、黄金、US100 各跑通一组模拟。重点验证“两边合约乘数不同”和“按最小手数取整后，强平缓冲不足”两种情况。仅仅把页面上的 BTC 改成品种下拉框，不算完成。
